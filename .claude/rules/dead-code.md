# デッドコード禁止

**使われていないコードを残さない。** 消したコードは Git の履歴に残っており、必要になれば復元できる。**「復元できる」ことが、消してよい根拠である。**

## 削除するもの

| 種類 | 例 |
|---|---|
| **コメントアウトされたコード** | `// const old = ...` の塊、旧実装の丸ごとコメントアウト |
| **未使用の変数・関数・クラス・型・定数** | どこからも参照されないもの |
| **未使用の `export`** | 外部公開しているが誰も import していないもの |
| **到達不能コード** | `return` 後の処理、常に false の条件分岐 |
| **未使用の依存パッケージ** | `package.json` / `go.mod` 等に残るだけのもの |
| **使われないフィーチャーフラグ** | 恒久的に true（または false）で固定され、分岐の片側が死んでいるもの |
| **スキップされたままのテスト** | `it.skip` / `xit` / `t.Skip` / `@Disabled` が放置されているもの |
| **旧実装** | 新実装に切り替えた後も「念のため」残している関数・ファイル |

## 「将来使うかもしれない」を残さない

- **今どこからも呼ばれていないコードは削除する。** 「あとで使う」「参考に残す」は理由にならない。**必要になった時点で書く方が、腐ったコードを直すより速い**。
- 使われていないコードは**保守コストだけを払い続ける**（リファクタ・依存更新・型変更のたびに巻き込まれ、レビューでも読まれ、検索結果を汚す）。
- **動いていないコードは壊れているかどうかも分からない**。テストもされないまま残り、いざ使おうとすると動かない。
- コメントアウトで残さない。**残す必要があるのは「なぜそうしなかったか」であり、それはコードではなくコメント・コミットメッセージ・issue で表現する**。

## 例外（残してよいもの）

以下は「未使用に見えるが必要」なもの。**削除する前に確認する**。

- **公開ライブラリ・SDK の API**（外部の利用者が使うため、リポジトリ内に参照がないのは正常）。
- **フレームワークの規約で呼ばれるもの**（DI で注入されるクラス、ルーティング規約で読まれるファイル、リフレクション・アノテーション経由の呼び出し、マイグレーションファイル）。静的解析が「未使用」と誤検出しやすい。
- **段階的移行の途中**で、削除時期が決まっているもの。**期限と削除条件をコメントに書き、issue を立てて追跡する**（書かないなら残さない）。
- **意図的に残す将来用のインターフェース**は、**その判断と理由をコメントに書く**。書けないなら残さない。

## 検出

- Linter の未使用検出を有効にする（未使用変数・未使用 import・到達不能コード）。詳細な運用は `static-analysis.md` に従う。
- **未使用の `export` は通常の Linter では検出できない**。プロジェクト全体を横断して調べる専用ツール（TypeScript の `knip` / `ts-prune`、Go の `deadcode`、Python の `vulture` 等）を使う。
- **本プロジェクトは `knip` を導入済み**（#115）。未使用の `export`・ファイル・依存関係を検出し、CI の `static-check` ジョブで**必須**にしている（`pnpm knip` / 手元では `make knip`。設定は `front/knip.jsonc`）。
  - **フレームワーク規約の export は除外しない。** `page.tsx` の `default`・`route.ts` の HTTP メソッド・`metadata`・設定ファイル等は、knip の Next.js / Vitest / Playwright プラグインがエントリとして扱う。上記「例外」に当たるからといって、手で除外を足さない。
  - **除外は「ツールから見えない外部要因」に限る**（gitignore された生成物から参照される依存・npm 外で入れる CLI 等）。`knip.jsonc` に**項目単位で**足し、理由をコメントで書く（抑制コメントの作法と同じ。`static-analysis.md`）。ディレクトリ・ファイル単位で検査対象から外さない。
  - 検出されたら**除外ではなく削除で解消する**。「1 ファイル内でしか使わない型・定数の `export`」も対象（`export` を外す。置き場所の判断は `typescript.md`「型定義の配置」「定数の配置」に従う）。
- **カバレッジ 0% の行はデッドコードの候補**。テストカバレッジレポートを、未使用コードの発見にも使う。

## レビュー観点

- コメントアウトされたコードが含まれていないか（**指摘したら削除する。「残しておいて」は受け入れない**）。
- 「将来のため」に追加された、今どこからも呼ばれない関数・引数・オプションがないか。
- 置き換え実装を入れた PR で、**旧実装が削除されているか**（新旧併存のまま終わっていないか）。
- スキップされたテストが放置されていないか。
- `front/knip.jsonc` の除外が、理由なく・広い単位で足されていないか（knip を黙らせるための除外になっていないか）。
