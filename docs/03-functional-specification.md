## ユーザーフロー（画面遷移）

### 一般ユーザー

- 一覧 → 詳細（「詳細を見る」）
- 詳細 → 一覧（「一覧へ戻る」）
- 一覧 → カレンダー（サイドバーの「カレンダー」）
- カレンダー → 詳細（記録がある日のクリック）
- 一覧 → 推移グラフ（サイドバーの「推移グラフ」）

### 管理者

- 一覧 → 管理者ログイン（ヘッダー右上リンク）→ 一覧（ログイン成功時）
- 一覧 → 記録追加（一覧上部「記録追加」）→ 一覧（保存後）
- 詳細 → 記録編集（「編集」ボタン）→ 詳細（保存後）
- 記録一覧(管理操作) → 記録編集（「編集」）→ 記録一覧(管理操作)（保存後）
- 記録編集の保存後の遷移先と戻りリンクは遷移元で切り替える（#32）。詳細から入った場合は `?from=detail` を付けて遷移し、詳細へ戻る。`from` が無い・`detail` 以外の値の場合は記録一覧(管理操作)へ戻る（クエリの値を遷移先 URL として使わない）。
- 管理者メニュー → 記録一覧(管理操作) / 記録追加 / プロフィール / マスター管理 / ログアウト

### 制御

- 未ログインで管理者 URL にアクセスした場合はログイン画面へリダイレクト。
- 管理者メニューはログイン後のみ表示（一般ユーザー非表示）。
- ログアウト導線は画面右上に固定表示。
- 主な編集導線は一覧/詳細画面から直接行う（管理者メニューは補助的な位置付け）。

## 機能詳細（画面別仕様）

### 一覧

- トップページ（`/`）。1 ページ目は一覧の上にダッシュボードを表示する（#27）。2 ページ目以降は一覧のみ。
  - **今週のサマリー**: 今週（月曜始まり。月曜〜今日）のトレーニング回数（記録がある日数）・合計セット数・推定消費カロリー合計と、それぞれの先週比（%）。
    - 先週比は先週の 1 週間全体ではなく「先週の月曜〜先週の今日と同じ曜日」と比べる（週の途中でも同じ日数どうしで比較する）。
    - 先週の値が 0 の場合は比を定義できないため「先週は記録なし」と表示する。増減はアイコン＋「先週比 +N%」の文言で示し、色だけで伝えない。
    - 推定消費カロリーはプロフィールの体重（現在値）で算定する。体重が未設定なら「-- kcal」（先週比なし）。
    - 「今日」はブラウザのローカル日付で決める。
    - 先頭に連続記録日数（ストリーク、#28）を炎アイコンと「N日連続記録中」で表示する。今日を起点に記録が途切れずに続く日数で、今日が未記録でも昨日まで続いていれば継続中とし「今日記録すると N+1 日になります」と促す。今日も昨日も未記録なら「連続記録はまだありません。今日から始めましょう」。
  - **今月の記録（ヒートマップ）**: 今月の日を小さなマス目（日曜始まり）で並べ、記録がある日を塗る。塗られた日は詳細へのリンク。今日は黒い枠で示す。「カレンダーで見る」でカレンダー画面へ。
    - 連続記録中の日はピンクのマスに白い点を付けて示し（色と形の両方で区別する）、凡例「記録あり / 連続記録中 / 今日」を添える。
  - **最新の記録**: 一覧の先頭（最新）の日付と、筋トレ・有酸素メニューを表示し、詳細へのリンクを置く。
- 並び順は日付の新しい順（降順）、1 日 1 カード表示。
- 表示項目: 日付 / 筋トレメニュー一覧 / 有酸素メニュー一覧 / 推定消費カロリー / 詳細ボタン。
  - 筋トレメニュー一覧: 各行の部位・種目・セット数・回数・重量。
  - 有酸素メニュー一覧: 各行の種別・時間・距離（複数行対応）。
  - 該当する明細が無い日は「筋トレの記録なし」「有酸素の記録なし」を表示する。
  - 合計セット数・有酸素合計時間・合計距離のサマリー表示は行わない（#23 で廃止）。
  - 管理者向け記録一覧(管理操作)のカードも同じメニュー表示とする（推定消費カロリーは表示しない）。
- 空状態文言: 「記録がありません。最初の記録を追加しましょう」。
- 管理者は一覧上部に「記録追加」ボタンを表示。
- ヘッダーはタイトル＋管理者ログインリンク（右上）。
- 詳細ボタン文言は「詳細を見る」。
- 推定消費カロリーをカード下部に表示。
- ページング: 1 ページ 10 件、前へ/次へボタンで切替。

### 詳細

- 並び順: 日付 → 筋トレ一覧 → 有酸素一覧 → 体調メモ。
- 筋トレ一覧はカード/リスト形式（表示順: 種目 → 部位 → セット → 回数 → 重量、ラベル付き・単位付き）。
- 有酸素一覧は複数行表示（種別/時間/距離をラベル付き・単位付きで行ごとに表示）。
- 体調メモが空の場合は「体調メモなし」を表示。
- ヘッダーはタイトル＋戻るリンク（「一覧へ戻る」）。
- 推定消費カロリーを上部に表示。
- 管理者向けに「編集」ボタンを表示（クリックで記録編集画面へ遷移）。

### 記録追加 / 記録編集

- 記録追加と記録編集は同一フォームを共用（編集時は既存データをプリセット）。
- 日付初期値は今日（ブラウザのローカルタイムゾーン基準。UTC 換算はしない）。DatePicker で別の日付に変更できる。編集時は既存の日付をセットし変更不可。
- 筋トレ行は初期表示で 1 行、最少 1 行を維持（全削除不可）。
- 有酸素行は初期表示 0 行（追加ボタンで追加）、全削除可能（任意項目のため）。
- 体調メモの入力 UI はテキストエリア。
- 選択肢はマスター管理の内容と連動する（#6）。画面を開くたびに `GET /api/masters` で取得するため、マスターの追加・編集・削除は次に開いたときから反映される。
  - 部位: 部位マスターのプルダウン（名称昇順。先頭は「選択」）。
  - 種目名: 種目マスターを入力候補（`<datalist>`）として表示し、マスターに無い種目の自由入力も受け付ける（種目マスターは部位とひも付かないため）。
  - 有酸素種別: 有酸素種別マスターのプルダウン。行追加時の既定値はマスターの先頭で、マスターが未取得・0 件なら未選択。
  - 保存済みの値がマスターに無い場合（マスター側で削除・改名された場合）も、その値を選択肢に残して表示する（編集画面を開いただけで値が置き換わらないようにするため）。
  - マスターの取得に失敗した場合は「選択肢を取得できませんでした。」を表示する。取得できた種別の選択肢と保存済みの値はそのまま使える。
- 記録追加画面に「前回の記録をコピー（YYYY-MM-DD）」ボタンを置く（#26）。最新の記録（日付降順の先頭）の筋トレ行・有酸素行をフォームに流し込み、差分だけ修正して保存できるようにする。
  - 日付とメモはコピーしない（日付はユーザーが選ぶ）。
  - 最新の日付は画面を開いたときに `GET /api/records?page=1` で取得し、明細はボタン押下時に `GET /api/records/{date}` で取得する（押下時点の内容を使う）。新規 API は追加しない。
  - 筋トレ・有酸素に入力がある場合は「入力中の筋トレ・有酸素を前回の記録で置き換えます。よろしいですか？」と確認し、キャンセルなら何も変えない。筋トレ行がすべて空で有酸素行が 0 行なら確認しない（メモは判定に含めない）。
  - 記録が 0 件ならボタンを無効にし「コピーできる記録がありません。」を表示する。一覧の取得に失敗した場合もボタンを無効にし「前回の記録を取得できませんでした。」を表示する。
  - コピー成功時は「YYYY-MM-DD の記録をコピーしました。」、明細の取得失敗時（押下までに削除された場合を含む）はフォームを変えずに「前回の記録を取得できませんでした。」を表示する。
  - 前回の筋トレが 0 件なら空の筋トレ行を 1 行にする（最少 1 行）。
- 保存後は一覧へ戻る。
- ヘッダーはタイトル＋戻るリンク（「一覧へ戻る」）。
- 筋トレ/有酸素行の追加ボタンはセクション末尾、削除ボタンは各行の右端に配置。
- 入力ラベルを表示。
- フィールド単位のバリデーションエラーを各入力の下に赤文字で表示（保存ボタン押下後から表示）。エラーがある場合は保存を抑止。
- 日付ピッカーはモダンなカレンダー UI を使用し、年へのジャンプ操作を用意。
- 推定消費カロリーを画面下部に表示。

### カレンダー

- 画面: `/calendar`。表示月はクエリ `?month=YYYY-MM` で指定する。未指定・形式不正の場合はブラウザのローカル日付で今月を表示する（サーバーの UTC では決めない）。
- 月表示のカレンダー（日曜始まり。日付ピッカーと同じ並び）を表示。
- 記録がある日はハイライトとドットで表示し、クリックで詳細画面（`/records/{date}`）へ遷移する。記録の無い日はクリックできない。
- 今日の日付は枠で示す。
- 前月/次月ボタンで月を移動する（年をまたぐ）。移動は URL の `month` を書き換えて行うため、ブラウザの戻る/進むで前の月に戻れる。
- ヘッダーはタイトル＋一覧へ戻るリンク。取得失敗時は「記録の取得に失敗しました。」を表示する。

### 推移グラフ

- 画面: `/trends`。期間はクエリ `?period=1w|1m|3m|all` で指定する（未指定・不正は `1m`）。期間ボタンで切り替え、URL を書き換えるためブラウザの戻る/進むが効く。
- 期間の起点はブラウザのローカル日付の今日から求める（今日を含む直近 7 / 30 / 90 日。全期間は起点なし）。
- 指標ごとに 1 枚の折れ線グラフを表示する（合計セット数 / 有酸素距離 km / 推定消費カロリー kcal）。単位の異なる指標を 1 枚に重ねない（2 軸グラフにしない）。
- 横軸は記録がある日のみを並べる（記録の無い日を 0 で埋めない）。点の間隔は日数を表さないため、日付はツールチップと表で示す。
- 各グラフはホバーで日付と値のツールチップを出し、「表で見る」で同じ値を表でも確認できる。
- 推定消費カロリーは一覧・詳細と同じ算定で、プロフィールの体重（現在値）を全期間に使う。体重が未設定なら「推定消費カロリー: プロフィールで体重を設定すると表示されます」を表示する。
- 期間内に記録が無ければ「この期間の記録はありません」を表示する。取得失敗時は「記録の取得に失敗しました。」。
- 体重の推移は、体重の履歴を持たないため未対応（#178）。

### 管理者メニュー

- ログイン後のみ表示（一般ユーザー非表示）、カード/ボタンのグリッド。
- 並び順: 記録一覧(管理操作) → 記録追加 → マスター管理 → ログアウト。
- カード文言は短い名詞で統一。ログアウト導線は画面右上に固定表示。

### マスター管理

- 「部位」「種目」「有酸素種別」のタブ切替。初期値を用意し管理者が編集可能。
- 一覧はリスト表示（名称 + 編集/削除アイコン）。追加は一覧上部の入力＋追加ボタン、編集はインライン編集、削除は確認ダイアログ。
- 追加入力のプレースホルダー「新しい項目を追加」、削除確認文言「この項目を削除します。よろしいですか？」。

### プロフィール

- 体重（kg）を入力・保存。データは 1 件のみ維持（上書き）。

## ビジネスロジック

### 入力 / バリデーション

- 数値項目: セット数、回数、重量、時間、距離。小数入力を許可。
- 有酸素種別は有酸素種別マスターから選ぶ（初期値「ラン/ウォーク」）。時間・距離のいずれかを入力した行は種別が必須（「種別を選択してください」）。
- カロリー算定の METs 係数はラン / ウォークのみ定義している。マスターに追加した他の種別は係数を持たず、推定消費カロリーは 0 として扱う。
- 1 日に複数の筋トレ項目・複数の有酸素項目を追加可能。
- バリデーションはフィールド単位でエラー表示（どの項目がエラーか分かるようにする）。
- エラー表示は保存ボタン押下後から開始（初期表示ではエラーを出さない）。エラーがある場合は保存を抑止。
- 同日保存時はエラーとして弾き、通知 UI を表示する。
- 実装: `front/src/validation/record.ts`（純粋関数）、`front/src/types/recordForm.ts`（フォーム行・エラーの型）、`front/src/hooks/useRecordValidation.ts`（状態管理）。

### 単位

- 重量 = kg / 距離 = km / 時間 = 分。

### 推定消費カロリー（目安）

目安（概算）で算出する。体重はプロフィール（Supabase）に保存した値を使用。一覧/詳細/記録追加の全てに「推定消費カロリー」ラベルで表示する。

#### 有酸素（時間ベース）

- `消費カロリー = METs × 体重(kg) × 時間(時間)`
- METs は種別ごとの固定値（暫定）: ラン = 8.0 / ウォーク = 4.0。
- 未知の種別は MET = 0（カロリー 0）。

#### 筋トレ（概算）

- `消費カロリー = 体重(kg) × 0.1 × セット数合計`（セット数合計はその日の合計）。

#### 表示

- 一覧はカード下部、詳細は上部、記録追加は画面下部に表示。
- 整数に丸めて「N kcal」形式で表示（実装: `front/src/lib/calorie.ts`）。
- 未決定: METs 係数の調整。
